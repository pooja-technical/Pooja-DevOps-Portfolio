PROJECT 01 / AWS / CLOUD

AWS 3-Tier
Architecture

Designed and implemented a three-tier application architecture on AWS using separate layers for presentation, application processing and database services.

AWS VPC EC2 Load Balancer RDS Networking

Project Objective

The objective was to understand how a scalable and secure application can be structured on AWS by separating the presentation, application and database layers.

The architecture was designed to isolate resources into appropriate network layers while allowing controlled communication between them.

What I Built

🌐 VPC

Created a dedicated AWS VPC to provide an isolated network environment for the application.

⚖️ Load Balancer

Used a load balancer to distribute incoming application traffic across available instances.

💻 EC2

Used EC2 instances to host the application layer of the architecture.

🗄️ RDS

Used Amazon RDS as the database layer, keeping database resources separate from the application layer.

Networking & Security

  • Designed separate network layers for different application components.
  • Configured routing and connectivity between required resources.
  • Used security controls to restrict unnecessary access between layers.
  • Applied the principle of allowing only required communication between components.

Scalability

A three-tier architecture provides a foundation for scaling individual layers independently. The application layer can be expanded without directly exposing or modifying the database layer.

Key Learnings

☁ AWS Networking

Improved my understanding of VPCs, subnets, routing and connectivity.

🔐 Security

Learned why application components should not all be directly exposed to the internet.

📈 Architecture

Understood how separating application layers improves organization and scalability.

🛠 Hands-on Practice

Gained practical experience working with AWS infrastructure components.
